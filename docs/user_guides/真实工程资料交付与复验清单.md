# 真实工程资料交付与复验清单

适用仓库：`/home/cj/my-pele`

这份清单面向真实工程闭合阶段：当你准备把真实 CAD、边界条件、外部泄漏扩散实验数据、火灾/过压标定数据交给程序时，按这里的路径放文件、按这里的命令复验。它不是新增物理模型，而是把当前仓库已经存在的 strict intake kit 和验证门禁整理成可操作流程。

## 6. 常见失败和处理

### 6.1 sha256 mismatch

含义：某个底层文件被改了，上层报告还引用旧哈希。

处理：

```bash
cd /home/cj/my-pele
bash tools/rebuild_engineering_h2_evidence_chain.sh
bash tools/verify_master_plan_current_scope.sh
```

如果是 strict 外部资料相关，再跑：

```bash
bash tools/run_current_scope_release_refresh.sh
```

### 6.2 missing artifacts

含义：模板存在，但真实文件没有放到目标路径。

处理：对照本清单和 `strict_external_artifact_drop_checklist_report.md`，把目标文件补齐。

### 6.3 validates=False

含义：文件存在，但字段、单位、哈希、行数、标签配对或 provenance 不满足 gate。

处理：先打开对应 `*_template.*`，按模板列名补齐，不要改列名；再重跑对应单项复验。

### 6.4 NOT_READY 状态

含义：该资料包还不能清 blocker。`NOT_READY` 不一定代表程序坏了，通常代表真实数据还不完整或字段对不上。

处理：打开对应 `*_report.md`，查看 `Missing Artifacts` 或 `Quality Gates` 小节。

## 7. 最终闭合判断

真实资料进入后，如果要判断当前工程生产级 strict 缺口是否真正闭合，至少要同时满足：

```text
verify_engineering_h2_production_evidence.sh PASS
verify_master_plan_current_scope.sh PASS all current-scope verification gates
run_current_scope_release_refresh.sh 最终 CURRENT_SCOPE_RC=0
strict external artifact checklist missing files = 0
real CAD cleanup package ready
external plume benchmark ready
fire calibration dataset/package ready
```

如果只有 smoke 算例 PASS，但真实 CAD、外部 plume、火灾标定仍是 `NOT_READY`，只能说明当前程序和算例链路可运行，不能说明 strict 真实工程闭合已经完成。
